# Validation record

## Saved examples

The two included JSON files were freshly generated by the public MATLAB/Dynare bridge after the refactor. The automated checks verify:

- status is successful and no solver variables are reported missing;
- 82 observations per model series (initial, 80 transition periods, terminal);
- 132 variables in each catalog, with identical names and order;
- every raw and transformed value is finite;
- every catalog variable has a matching series and no extra series exists;
- unilateral tariff path: gross `τ₂₁` moves from 1.00 to 1.10 while `τ₁₂` remains 1.00;
- bilateral tariff path: both gross tariffs move from 1.00 to 1.10.

Run:

```powershell
python scripts\validate_saved_examples.py
python -m unittest discover -s tests -v
```

## Source/public numerical comparison

`scripts/compare_reference_results.py` compares every period of every raw series and fails if catalogs or dimensions differ or if an error exceeds `atol + rtol × |reference|`. The initial documented tolerances are `atol=1e-8` and `rtol=1e-7`; any relaxation must be justified by a recorded MATLAB/Octave/Dynare version difference.

On 2026-08-07, the 80-period unilateral scenario was run independently through (1) an isolated copy of the original source MATLAB bridge and (2) the renamed public bridge. MATLAB R2026a and Dynare 6.4 produced identical values at every period for all 132 raw series; the largest absolute error was `0`, and all summary metrics also matched exactly.

The previously copied sample JSON did not match this fresh source run and was therefore not retained as public validation data. Both public saved examples were regenerated from successful current-model solves and then relabeled as saved results.

Octave/Dynare cross-engine certification remains pending because GNU Octave is not installed in the current validation environment. Before release, run both scenarios under the documented supported Octave/Dynare combination and record versions and any numerical differences here.

The direct MATLAB bridge and the FastAPI validation/metadata/saved endpoints were tested separately. An end-to-end FastAPI worker launch remains to be certified outside the current managed desktop environment: MATLAB R2026a reported a startup-level filesystem inconsistency when launched as a nested Python subprocess here, while the identical `matlab -batch` bridge command completed normally when launched directly. Solver failures remain explicit and never fall back to saved or synthetic data.

No test or runtime path substitutes synthetic output after failure.
